Scenario Editor

Build automation without writing a line of code.

The Q-Bot web interface lets any tester create a scenario in minutes — no scripting, no XPath selectors, no brittle element IDs.

  • Upload a screenshot of the target app screen as the step background
  • Place numbered tap points by clicking directly on the screenshot
  • Set millisecond-precision wait times between actions to match real app behaviour
  • Add, reorder, and remove steps at any time
  • Scenarios are saved and versioned in the Q-Bot backend
  • Step images stored locally on the Q-Bot device — no cloud uploads

The result is a reusable, named scenario — a visual map of what to tap and when — ready to be triggered on demand from any test pipeline.

Real-Device Execution

Not a simulator. The actual app, on actual hardware.

Q-Bot drives a real Android device over USB using ADB — Android Debug Bridge. Every tap and swipe is delivered to the physical screen of a real device running your real 2FA app.

  • Operates the genuine 2FA application, not a mock or stub
  • Touch actions delivered via ADB: tap, swipe, wait
  • Works with any Android 2FA app — banking, enterprise SSO, LuxTrust, authenticators
  • App-level security checks, certificate pinning, and biometric prompts behave as in production
Why this matters: Simulators lie. Production 2FA apps behave differently from mocks. Q-Bot operates in the same environment your users do.

REST API Integration

One HTTP call. Any pipeline. Any framework.

Every scenario in Q-Bot is accessible via a simple REST API. No SDK, no proprietary plugin, no agent to install in your CI environment.

Three endpoints are available for external use:

EndpointDescription
GET /scenarios/:id/executeRun a saved scenario on the connected device
GET /get-luxtrust-otpReturn the current OTP from the LuxTrust app
POST /display-imageDisplay a QR code on Q-Bot's screen for the Android device to scan
  • Self-hosted, runs on your local network
  • No authentication tokens or API keys required
  • Compatible with Selenium, Cypress, Playwright, Robot Framework, JUnit, shell scripts, and more
  • Integration takes under an hour
# Selenium (Python) example
import requests

# Trigger 2FA scenario
requests.get(
  "http://q-bot.local:8000"
  "/scenarios/42/execute"
)

# Test continues normally
driver.find_element(
  By.ID, "dashboard"
).is_displayed()
Bluetooth Companion App

Let Q-Bot react to 2FA notifications the moment they arrive.

The optional Q-Bot companion app runs on a second Android device. Using Android's Accessibility Service, it monitors notifications from 2FA apps and notifies Q-Bot over Bluetooth Low Energy when one is detected.

  • Monitors 2FA app notifications via Android Accessibility Service
  • Sends trigger to Q-Bot over BLE — no call from the test runner needed
  • Ideal when 2FA timing is unpredictable or controlled by the app under test
  • Supports auto-reconnect to the paired Q-Bot device
  • Both BLE and API triggers can be used in the same environment

Hardware Stack

Q-Bot is a complete, self-hosted system. Everything stays on your local network.

Self-hosted on Raspberry Pi

All services run as Docker containers on Raspberry Pi OS Lite. Single Docker Compose command to deploy and update.

No cloud dependency

No external API calls, no data leaving your environment, no internet connection required during test runs.

Complete stack included

Web UI, backend API with SQLite storage, BLE service, and a small attached screen for displaying QR codes — all in one device.
