Comment ça marche

Comment Q-Bot franchit l'étape 2FA

Du parcours de connexion bancaire à la campagne de tests de nuit, voici comment des équipes QA automatisent l'authentification à deux facteurs avec Q-Bot.

Le principe

Comment ça marche

Votre chaîne de tests garde la main de bout en bout. Q-Bot ne prend le relais que sur l'étape de double authentification, puis la rend.

1

Le test arrive à la 2FA

Le parcours automatisé atteint l'étape qui demande une validation sur smartphone. C'est là que les outils de test s'arrêtent.

2

Q-Bot est déclenché

Votre test appelle l'API, ou l'app compagnon détecte seule la notification qui vient d'arriver sur le téléphone.

3

Le scénario s'exécute sur le smartphone

Q-Bot rejoue les appuis et les temps d'attente enregistrés, dans la véritable application 2FA, par USB.

4

L'authentification est validée

La demande est approuvée sur le téléphone, ou le code à usage unique est récupéré et renvoyé à votre test.

5

Le test continue

Le parcours reprend là où il s'était arrêté, sans personne devant l'écran, de jour comme de nuit.

Cas d'usage

Dans quels cas l'utiliser

Cinq situations où la chaîne se débloque : une connexion avec LuxTrust, une notification à valider, un code à usage unique à récupérer, un parcours à QR code, une campagne de nuit.

Banque et fintech

Une connexion testée de bout en bout, 2FA comprise

Le blocage

Chaque test de connexion passe par une étape 2FA : une notification à valider, un code de Microsoft ou Google Authenticator, une demande LuxTrust ou itsme. Jouer ces tests sans personne devant l'écran voulait dire soit sauter la 2FA, ce qui vide le test de son sens, soit garder un testeur d'astreinte à toute heure.

Avec Q-Bot

L'app compagnon surveille l'application 2FA. Dès qu'une notification arrive, Q-Bot exécute le scénario de validation. Tout le parcours de connexion, 2FA comprise, se joue sans personne, sur un vrai appareil, à n'importe quelle heure.

0intervention humaine, à toute heure

Campagne de non-régression

Des exécutions de nuit vraiment automatiques

Le blocage

La campagne tourne à chaque demande de fusion et chaque nuit. Plusieurs parcours butent sur la 2FA : à l'authentification, sur une opération sensible, ou à l'élévation de session. Une seule étape manuelle casse toute la chaîne.

Avec Q-Bot

Chaque verrou 2FA de la chaîne devient un appel. Quand le test atteint l'étape, il envoie GET /scenarios/:id/execute et Q-Bot s'en occupe. La campagne passe ou échoue sur la logique de l'application, et non plus sur l'absence d'un humain.

1 appelpar verrou 2FA dans la chaîne

Code LuxTrust

Le code à usage unique dans vos assertions

Le blocage

Les parcours qui passent par LuxTrust, courants dans la finance, l'administration et les grandes entreprises au Luxembourg, ont besoin du code affiché pour remplir un formulaire ou vérifier une réponse d'authentification. Aller le lire à la main interrompt le test.

Avec Q-Bot

Appelez GET /get-luxtrust-otp à l'endroit du test où le code est nécessaire. Q-Bot lit le code affiché par l'app LuxTrust sur le téléphone relié et le renvoie dans la réponse. Votre outil de test s'en sert directement.

Quelques spour récupérer le code affiché

Authentification d'entreprise

Les parcours à plusieurs facteurs

Le blocage

Les applications d'entreprise enchaînent souvent mot de passe, validation par notification, puis code temporaire. Automatiser cela de bout en bout demande d'orchestrer plusieurs écrans : fragile en script, lent à la main.

Avec Q-Bot

Chaque étape est un scénario, construit visuellement. Votre outil de test les appelle dans l'ordre par l'API. Q-Bot joue chacune avec les bons temps d'attente, et le parcours complet se termine sans intervention.

3 scénariosenchaînés dans l'ordre, sans script

2FA par QR code

Afficher, scanner, continuer

Le blocage

Certains parcours 2FA demandent au téléphone de scanner un QR code : pour confirmer une transaction, appairer une application d'authentification ou valider une session. Présenter un QR code à un appareil sous test automatisé n'a pas de solution évidente.

Avec Q-Bot

La chaîne envoie l'image à Q-Bot par POST /display-image. Q-Bot l'affiche en plein écran sur son petit écran intégré. Un scénario demande alors au téléphone d'ouvrir sa caméra et de la pointer dessus : le scan se fait, l'étape 2FA se résout.

1 écranle boîtier affiche, le téléphone scanne

Déclenchement

Deux modes de déclenchement

Un appel depuis votre chaîne de tests, ou rien du tout : l'app compagnon s'en charge dès qu'une notification 2FA arrive sur le téléphone.

Depuis votre chaîne de tests

Un appel HTTP au moment où le test atteint l'étape 2FA. Explicite, déterministe, facile à insérer dans n'importe quelle chaîne.

  • GET /scenarios/:id/execute
  • Aucune clé, aucun agent à installer

Le cas détaillé : une connexion testée de bout en bout

Depuis le téléphone

L'app compagnon tourne sur l'appareil sous test et surveille les notifications des applications 2FA. Dès qu'une notification arrive, elle déclenche le scénario correspondant.

  • Aucun appel depuis votre chaîne de tests
  • Elle tourne sur le téléphone que Q-Bot pilote déjà : rien de plus à appairer
  • Utile quand le moment de la 2FA est imprévisible, ou décidé par l'application testée

Le cas détaillé : des exécutions de nuit vraiment automatiques

Les deux chemins coexistent dans le même environnement : à chaque scénario, celui qui lui convient. Dans les deux cas, les appuis partent vers le téléphone par ADB, l'outil standard d'Android pour piloter un appareil relié en USB. La boucle ci-contre montre le geste : la notification arrive, le scénario se joue, l'écran du téléphone change.

API REST

Un appel HTTP, et n'importe quelle chaîne de tests

Si votre outil sait faire une requête HTTP, il sait piloter Q-Bot. Aucun SDK, aucun greffon, aucun agent à installer.

L'appel, selon votre outil

Selenium (Python / Java) Appel requests ou HttpClient avant l'assertion
Cypress cy.request()
Playwright request.get() ou fetch()
Robot Framework Mot-clé RequestsLibrary
JUnit / TestNG RestAssured ou le HttpClient de Java
Shell / Bash curl
Toute chaîne CI/CD Une étape HTTP, une commande curl ou un script maison

Q-Bot est auto-hébergé : l'API répond sur le réseau où vous installez le boîtier, tant qu'il est allumé, sans dépendance extérieure. Elle n'attend aucune clé d'API : le contrôle d'accès est celui de votre réseau.
